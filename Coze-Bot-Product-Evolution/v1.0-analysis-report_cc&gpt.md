## 二、核心诊断：v1.0 缺少的关键模块

v1.0 本质上是一个 **无状态 RAG Bot**——"用户提问 → 知识库检索 → 模型回答"，没有状态流转、没有结构化采集、没有工程化控制。

### 2.1 缺失模块全景图

| 缺口 | 优先级 | v1.0 现状 | 影响 |
|------|--------|-----------|------|
| **状态机 (State Machine)** | 极高 | 无，仅靠 Prompt 自然语言描述"思考路径" | LLM 容易漏步骤、跳步、提前报价 |
| **结构化字段采集** | 极高 | 无，变量 `[]` 空 | 信息没采全就开始分析，结论不可靠 |
| **风险分级机制** | 极高 | 仅 Prompt 提到"红色信号"，无结构化规则 | 模型无法稳定执行风险判断 |
| **Function Calling** | 极高 | 无工作流 | 全靠模型聊天，不是"AI + 规则引擎" |
| **反幻觉约束** | 极高 | Prompt 仅禁止编造价格/周期 | 法规编号、检测标准、成分合法性等无约束 |
| **拒答机制/安全边界** | 高 | 无 | 用户要求规避监管、虚假宣传时无安全拦截 |
| **知识库优先级规则** | 高 | `auto_call: true`，但无引用规则 | 模型可能自己编法规依据 |
| **输出模板标准化** | 高 | 无 | 每次回复结构不同，体验不一致 |
| **成本控制** | 高 | 无 | 高频咨询场景 token 浪费严重 |
| **线索评分 (Lead Scoring)** | 中高 | 无 | 无法区分高价值客户和低价值询价 |

## 三、逐模块深度分析

### 3.1 状态机 (State Machine) — 缺失

**问题**：当前 Prompt 写的是"必须严格遵守以下思考路径，严禁跳步"，这是 Prompt 初学者典型误区。LLM 不是 BPM 工作流引擎，模型容易漏步骤、并行执行、提前报价、被用户打断后乱跳。

**建议**：引入 **对话状态机 (Conversation State Machine)**

```
S0：初始接待
S1：基础信息采集
S2：产品类别判定
S3：成分合规分析
S4：风险等级评估
S5：检测方案生成
S6：报价与周期预估
S7：咨询摘要生成
S8：转人工
```

**状态迁移规则**：
- 未收集核心字段时 → 禁止进入报价阶段 (S6)
- 出现高风险成分时 → 优先进入风险提示 (S4)
- 用户仅询问费用 → 可简化教育内容
- 用户为专业客户 → 减少基础解释冗余
- 用户问题超出消字号范围 → 进入边界提醒

**为什么关键**：这是"工程化 Prompt"与"普通 Prompt"的核心区别。它能降低模型乱跳、降低报价幻觉、降低 token 浪费、提高 Coze 多轮稳定性。这是企业 Agent 的骨架。

---

### 3.2 结构化字段采集 — 缺失

**问题**：v1.0 变量 `[]` 为空，Prompt 只是模糊地说"会了解产品类型和工作原理"，无法强制采集。

**建议**：定义必采字段 Schema

```json
{
  "customer_type": "品牌方/代工厂/中介机构",
  "product_name": "",
  "dosage_form": "",
  "main_ingredients": [],
  "target_claims": [],
  "usage_scenarios": [],
  "domestic_or_imported": "",
  "existing_reports": false,
  "need_filing": true,
  "need_testing_only": false,
  "budget_level": "low/medium/high",
  "urgency_level": "low/medium/high",
  "historical_rejection": false
}
```

**字段规则**：
- 必须优先采集：产品名称、剂型、核心成分、宣传功效
- 缺失关键字段时：不允许输出最终合规结论、不允许直接报价、不允许猜测法规状态
- 不允许基于猜测生成合规结论
- 不允许虚构成分法规状态

**为什么关键**：后续 Function Calling、RAG 检索、CRM、报价系统、自动生成咨询摘要都依赖结构化数据。否则 Agent 永远停留在"聊天机器人"，而不是企业系统。

---

### 3.3 风险等级引擎 — 缺失

**问题**：当前 Prompt 提到"六大红色信号"但太模糊，模型无法稳定执行。

**建议**：结构化风险分级

| 等级 | 触发条件 | 响应策略 |
|------|---------|---------|
| **R1 低风险** | 常规消毒成分、常规功效、无违规宣传 | 正常输出方案 |
| **R2 中风险** | 植物提取物、擦边功效、成分目录边界模糊 | 增加风险免责声明，建议技术审核 |
| **R3 高风险** | 医疗暗示、抗病毒/新冠、国外可用国内禁用、被其他机构退单、用户要求规避监管 | 禁止直接承诺，必须建议人工专家介入，禁止生成确定性结论 |

**为什么关键**：企业 Agent 的核心不是"回答问题"，而是"风险控制"。这是和普通客服 Bot 的最大差异。

---

### 3.4 Function Calling — 缺失

**问题**：v1.0 工作流 `[]` 为空，全靠模型聊天。企业级 Agent 不行。

**建议**：定义 5 个核心 Function

| Function | 输入 | 输出 |
|----------|------|------|
| `check_ingredient_compliance` | ingredients[] | status（allowed/restricted/prohibited）、risk_level、法规依据 |
| `classify_product` | product_info | category（抗抑菌剂/普通消毒剂）、need_permit、required_tests[] |
| `generate_testing_plan` | category + claims | 检测项目清单 |
| `generate_quote` | testing_items + urgency | 费用范围预估 |
| `generate_consult_summary` | session_data | 咨询诊断摘要 |

**为什么关键**：从"Prompt 驱动 Bot"升级为"AI + 企业规则引擎"，这是企业 AI 产品的核心差别。

---

### 3.5 反幻觉约束 — 薄弱

**问题**：当前 Prompt 只禁止"编造价格和周期、承诺 100% 通过率"，远不够。法规类 Agent 最大的风险就是幻觉——"这个成分可以做""这个宣传没问题"——一旦说错，直接商业事故。

**建议**：

```
禁编造清单：
- 编造法规编号
- 虚构检测标准
- 虚构备案政策
- 猜测成分合法性
- 虚构费用依据
- 承诺备案成功率

不确定时：
必须明确说明"当前知识库暂无明确依据，建议人工法规审核"
```

---

### 3.6 拒答机制 / 安全边界 — 缺失

**问题**：用户如果问"怎么绕备案""怎么规避抽检""怎么写擦边宣传"，当前无安全拦截。

**建议**：

```
以下情况禁止提供具体操作建议：
- 规避监管
- 虚假宣传
- 篡改检测结果
- 虚构备案材料
- 违规功效宣传

系统需：礼貌拒绝 → 提示法规风险 → 引导合法替代方案
```

---

### 3.7 知识库优先级规则 — 缺失

**问题**：涉及成分合法性、功效宣传、法规要求时，模型可能自己编而不引用知识库。

**建议**：

```
必须优先引用知识库的场景：
- 成分合法性判定
- 功效宣传合规性
- 检测项目明细
- 法规/标准要求
- 卫生许可证要求
- 备案流程步骤

若知识库无明确依据：
- 禁止编造
- 必须说明"需人工进一步确认"
```

---

### 3.8 输出模板标准化 — 缺失

**问题**：回复结构每次可能不同，企业最怕输出不稳定、客户体验不一致、无法沉淀数据。

**建议**：固定输出结构

```
# 初步合规诊断
## 产品类别
## 成分风险分析
## 功效宣传风险
## 推荐检测项目
## 是否涉及卫生许可证
## 预估周期
## 费用区间
## 当前风险等级
## 是否建议人工审核
## 下一步建议
```

---

### 3.9 成本控制策略 — 缺失

**问题**：上下文仅 3 轮、无变量存储，高频问答 token 成本不可控。

**建议**：

- FAQ 优先调用固定知识库答案（不重复生成）
- 专业客户减少科普解释
- 长对话自动生成阶段摘要，压缩上下文而不是无限增长
- 非关键问题不展开法规解释
- 相同问题避免重复生成长文本

---

### 3.10 线索评分 (Lead Scoring) — 缺失

**问题**：售前 Agent 的最终目的是服务销售转化，当前无法区分高价值线索和无效询价。

**建议**：

| 维度 | 示例 |
|------|------|
| 紧急程度 | 急单加分 |
| 预算 | 高预算加分 |
| 是否已有配方 | 加分 |
| 是否已有检测报告 | 加分 |
| 是否被退单 | 高价值线索 |
| 是否明确备案需求 | 加分 |

输出：`{ "lead_score": 82, "priority": "high" }`

## 八、核心结论

v1.0 的问题不是"写得不好"，而是**定位偏差**：

| | 当前 v1.0 | 建议 v2.0 |
|------|-----------|-----------|
| 定位 | AI 法规问答机器人 | 消字号合规预审引擎 |
| 架构 | 无状态 RAG Bot | 会话状态机 + Function Calling |
| 工程化 | Prompt 驱动 | AI + 企业规则引擎 |
| 价值 | 聊天 | 降低退单率 + 降低合规风险 + 降低人工售前成本 |
| 可扩展 | 无 | 可接 CRM / 报价系统 / 审核流 |

**最关键的三件事**：状态机、结构化字段采集、风险分级。这三件事不做，其他优化都是隔靴搔痒。
