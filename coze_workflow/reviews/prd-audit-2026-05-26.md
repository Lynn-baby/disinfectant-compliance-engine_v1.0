# PRD 漏洞审核报告

日期：2026-05-26
审核范围：消字号合规预审引擎 PRD v1.0 全文（~1700 行）
审核方法：逐节通读 + 交叉验证（代码实现 vs PRD 描述 vs 法规要求）

## 致命（会导致法规判定错误）

### #1 分类决策树 Step 1 关键词过于宽泛 ✅ 已修复（2026-05-28）

**位置**：3.3.0 第 170 行
**问题**：「口腔」「牙科」「眼科」「妇科」四个裸词会错误拦截正常产品。

例如：「口腔消毒喷雾」→ 被 Step 1 的「口腔」截获 → 分类为第一类（医疗器械/皮肤黏膜级）。法规上，只有用于**口腔黏膜消毒**的产品才属于第一类，普通口腔清洁/消毒产品属于第二类或第三类。

**影响**：所有涉及口腔/牙科/眼科/妇科的普通消毒产品都会错误升级到第一类，导致检测方案和法规路径全错。

**修复**：从 Step 1 关键词中移除四个裸词。同时新增 Phase 0 命名规范前置校验（卫生部《健康相关产品命名规定》第四条/第五条/第八条），在关键词分类之前拦截不合规产品名称。

---

### #2 Step 2 vs Step 3 优先级可能法规错误 ✅ 已修复（2026-05-28）

**位置**：3.3.0 第 229 行
**问题**：「消毒+抑菌同时命中 → 取 Step 2（抗抑菌制剂）」

法规上，宣称「消毒」的产品应按消毒剂管理，不因同时宣称「抑菌」而降级。抗（抑）菌制剂特指**不宣称消毒、仅宣称抑菌**的产品。

**影响**：同时宣称「消毒+抑菌」的产品被错误归类为抗抑菌制剂，检测方案缺少杀菌试验。

**修复**：Step 2 和 Step 3 合并为单一 Step 2（消毒剂/消毒器械/抗抑菌制剂并列），引入 resolve_conflict 机制。同时命中不同子类型关键词 → needs_review=True 转人工确认，禁止在 Code Node 内靠优先级消解。

## 严重（架构不一致 / 技术不可行）

### #3 PDF 生成方案在 Coze 环境不可行

**位置**：3.3.2 第 544 行
**问题**：「v1.0 用 Coze Code Node 调用 HTML → PDF 转换（Puppeteer 或等效服务）」

Coze Code Node 是 Python 3.11.3 运行时，Puppeteer 是 Node.js 库，两者不兼容。Python 标准库内置的 PDF 方案（reportlab）需要 pip install，Coze 不一定支持。

**修复方向**：A) 外置 HTTP 服务转 PDF B) v1.0 砍 PDF 仅输出 Markdown C) 验证 Coze 是否支持 reportlab

---

### #4 状态机回退机制（4.2.1）与问卷模式不兼容

**位置**：4.2.1 节（第 879-988 行）
**问题**：整套回退机制（变量冲突检测、修正确认子流程、级联 stale、自动重跑）是为多轮对话设计的——用户说「等一下，成分搞错了」。问卷模式中用户修改信息的方式是**重新提交整份模板**，触发全新 Workflow 请求，而非当前会话内的增量更新。

**影响**：4.2.1 的代码如果按 PRD 写，会在问卷模式下成为死代码。

**修复方向**：标注当前适用模式。区分「会话内增量修改」（保留）和「重新提交模板」（视为新请求全量重跑）。

---

### #5 S1 状态在问卷模式下语义不清

**位置**：4.1 状态机图（第 819 行）
**问题**：状态机显示 S0→S1→S2，S1 是「基础信息采集」。问卷模式中数据一次提交完成，Workflow 入口直接拿到完成的数据，不存在独立的信息采集状态。

**修复方向**：问卷模式下 S1 合并入 S0 或 S2。保留 S1 定义但标注「v1.1 多轮对话模式」。

---

### #6 多个 E2E 测试用例假设对话式交互

**位置**：10.3.2 业务边界场景测试
**问题**：以下用例描述多轮对话行为，问卷模式无法验证：

| 用例 | 描述的交互 |
|------|-----------|
| ID-E2E-EDGE04 | 追问×2 → 标注「未获取退单历史」 |
| ID-E2E-EDGE05 | 触发拆分追问 |
| ID-E2E-EDGE07 | 追问 → 不提供 → 不输出结论 |
| ID-E2E-SAFE05 | 正常输入后突然要求违规内容 |

**修复方向**：区分「单问卷提交路径」和「v1.1 多轮路径」的测试集。

---

### #7 异常流 5.1.5 套装拆分与问卷模式不兼容

**位置**：5.1.5 节（第 1111-1118 行）
**问题**：依赖关键词检测触发追问拆分，但问卷模板是单产品模板。

**修复方向**：用户提交「XX套装」时直接提示「请为每个产品单独填写模板」，而非尝试对话式拆分。

---

### #8 降级策略引用过时的 Prompt 回退模式

**位置**：5.2 节（第 1143 行）
**问题**：「Workflow 执行失败 → 回退到 Prompt 驱动的纯文本分析」。问卷模式下数据不进 LLM，不存在 Prompt 备选路径。

**修复方向**：降级方案改为「固定错误提示 + 建议联系人工 + 保留已提交数据」。

## 一般（边界情况缺失 / 细节不完整）

### #9 安全扫描范围未定义

**位置**：3.4.0 阶段 1
**问题**：问卷模式下，安全扫描的输入是整个模板文本。没有定义是否逐字段扫描、还是全文本扫描。如果用户「使用场景」写「医院」，会不会被误判为医疗暗示？

**修复方向**：明确安全扫描是全文本匹配还是分字段匹配。

### #10 entry_merge Code Node 测试用例缺失

**位置**：10.2 节
**问题**：10.2 包含 7 个子节的测试规格（安全/Gate/风险/成分/检测/宣称/报价/PDF），但没有入口解析（模板正则解析 + 归一化 + 剂型校验）的测试规格。代码已有（entry_merge.py, 12/12 pass），PRD 未收录。

**修复方向**：新增 10.2.X 入口解析测试规格。

### #11 问卷模板用户视图缺失

**位置**：全文
**问题**：PRD 反复提及「固定问卷模板」但从未定义用户看到什么。entry_merge.py 定义了服务端解析格式，用户界面未文档化。

**修复方向**：新增附录或 Bot Persona 文档定义模板的用户视图。

### #12 Bot Persona Prompt 缺失

**位置**：全文
**问题**：当前架构依赖 Bot 展示模板、转发提交、展示结果。但 PRD 不含 Bot 行为规范（如何处理非模板消息、「帮助」「价格」追问、错误重试策略）。

**修复方向**：新增 Bot Persona 文档或 PRD 章节。

---

### #13 usage_scenarios 参与分类但不强制采集

**位置**：3.3.0 + 4.3
**问题**：分类决策树输入包含 `usage_scenarios`，但该字段是选采的（4.3）。用户不填时，Step 1 的医疗场景关键词无法从该字段匹配，导致第一类产品漏判风险。

**修复方向**：要么将 usage_scenarios 升级为必采，要么分类决策树不再依赖它，仅依赖 product_name + target_claims + dosage_form。

### #14 S6 报价内容与 MVP 范围声明矛盾

**位置**：3.3.2 节（~200 行）+ 状态机图 + 测试 10.2.7/10.2.8

**修复方向**：如 MVP 真砍 S6，PRD 将 S6 标记为「v1.1」或移到单独页面。状态机图更新。

### #15 Section 10.2 测试用例中的 Gate 测试描述过时

**位置**：10.2.2 第 1312 行
**问题**：Gate 测试描述「给定变量状态 → 验证 Gate 是否放行」，这是旧的变量传参模式。问卷模式下 Gate 的输入是 `parse_structured_text` 的返回值，测试应改为「给定模板文本 → 验证解析 + Gate 结果」。
