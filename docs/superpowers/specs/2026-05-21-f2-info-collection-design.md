## 1. 概述

F2 负责消字号合规预审引擎 S1 阶段的信息采集。6 个必采字段 + 4 个选采字段，通过双入口设计覆盖"急着要报价"和"先了解再定"两种用户心态。

### 必采字段（按优先级）

| 优先级 | 字段 | 说明 |
|--------|------|------|
| P0 | `main_ingredients` | 核心成分，INCI 名或 CAS 号 |
| P1 | `dosage_form` | 剂型：液体/片剂/粉剂/凝胶/喷雾/湿巾/其他（依据 GB 38598-2020 §3、2006 规范 §[剂型型号]） |
| P2 | `domestic_or_imported` | 国产/进口，决定合规路径分叉 |
| P3 | `target_claims` | 宣称功效：消毒/抗菌/抑菌/清洁/其他 |
| P4 | `product_name` | 产品名称，仅用于报告抬头 |
| P5 | `customer_type` | 品牌方/代工厂/中介/其他，影响报价权限 |

### 选采字段

`usage_scenarios`, `existing_reports`, `historical_rejection`, `urgency_level`

## 2. 整体流程架构

```
用户进入
  │
  ▼
┌─────────────────────────┐
│  S0 开场白              │
│  您想：                 │
│  A. 直接出预审报告      │
│  B. 先了解流程          │
└───────────┬─────────────┘
            │
    ┌───────┴───────┐
    ▼               ▼
┌────────┐    ┌──────────────┐
│ 通道 A  │    │ 通道 B       │
│ 快速报价│    │ 先聊再定     │
└───┬────┘    └──────┬───────┘
    │                │
    └────────┬───────┘
             ▼
┌─────────────────┐
│ NLU 实体抽取     │  GLM-4-flash，每轮都跑
└────────┬────────┘
         ▼
┌─────────────────┐
│ Gate 校验        │  Code Node
│ 6 字段全 → S2   │
│ 缺 → 追问        │
└─────────────────┘
```

**规则：**
- 通道 A/B 随时可切换，共享同一个 session 变量池
- S0→S1 的触发条件不变，两入口均在 S1 阶段内

## 3. 通道 A：快速报价

### 3.1 引导模板

用户选 A 后输出：

```
好的，请提供以下信息。您可以直接粘贴成分表，我来提取：

▸ 产品名称：
▸ 剂型（液体 / 片剂 / 粉剂 / 凝胶 / 喷雾 / 湿巾 / 其他）：
▸ 核心成分（INCI 名，多个用逗号分隔）：
▸ 宣称功效（消毒 / 抗菌 / 抑菌 / 清洁 / 其他）：
▸ 国产还是进口：
▸ 您的角色（品牌方 / 代工厂 / 中介 / 其他）：

【暂时无需报价，先跳过】
```

底部"先跳过"按钮是通道 B 的入口。

### 3.2 追问策略

- 每次只追一个字段，按 P0→P5 顺序
- 追问话术：`"好的，您提到了 XXX。还缺一个关键信息：**[字段说明]**（[选项]）"`
- 三轮追问硬上限：三轮后仍有缺 → 标记 `partial_info = true`，输出加免责声明，不阻塞流程
- P0-P2 至少需要集齐，否则阻断进入 S2

### 3.3 用户粘贴后处理

NLU 从自由文本中抽取所有可识别字段 → Gate 校验 →：
- 齐全 → 进入 S2
- 缺字段 → 按优先级追问
- 有冲突 → PRD §4.2.1 修正确认子流程

## 4. 通道 B：先聊再定

### 4.1 后台静默抽取

- 每轮用户输入额外跑一次 GLM-4-flash 实体提取
- 抽到的字段静默写入 session 变量
- **不暴露抽取结果，不追问，不打断聊天节奏**
- 正常回复法规问题、解释流程，不走判定链路

### 4.2 字段集齐提醒

6 个必采字段静默集齐后，下一轮回复末尾追加：

```
"对了，这段时间您提供了不少产品信息，我现在可以帮您出一份完整的预审报告和报价区间，需要吗？"
```

- 用户同意 → 复述已集齐字段请用户确认 → Gate 校验 → S2
- 用户拒绝 → 保持通道 B，字段值不清除
- 用户主动说"给我报价" → 立即切通道 A，Gate 校验当前字段

### 4.3 状态边界

| 条件 | 行为 |
|------|------|
| 字段始终不齐 | 永久停留在咨询模式，不推进 |
| 字段集齐 + 用户同意 | 切链路模式，跑 Gate 校验 |
| 用户主动要求报价 | 立即切换通道 A |

## 5. 技术实现要点

### 5.1 Coze 平台映射

| 组件 | 实现方式 |
|------|---------|
| S0 开场白 + 分支 | LLM Node → If-Else Node（intent = REPORT / CONSULT） |
| 通道 A 引导模板 | LLM Node，固定 system_prompt 输出结构模板 |
| 通道 B 对话 | LLM Node，标准对话 prompt |
| NLU 实体抽取 | Code Node / LLM Node（GLM-4-flash），输出结构化字段 |
| Gate 校验 | Code Node（JavaScript），纯逻辑校验 |
| Session 变量池 | Coze 变量系统，6 必采 + 4 选采 |
| "先跳过"按钮 | Coze 快捷回复 / 底部固定选项 |

### 5.2 与后续状态的接口

- S1 → S2 的前置条件：`product_name` + `dosage_form` + `main_ingredients`（P0-P2）非空
- S1 输出的 session 变量供 S2-S6 全链路使用
- 缺字段标记 `partial_info = true` 时，S4/S5/S6 输出加免责声明

## 6. 异常处理

- 用户输入完全不含可抽取字段 → 正常回复 + 不写入任何变量
- 用户连续 5 轮未提供任何新字段（通道 B）→ 不提示，继续等待
- 用户要求清空重来 → 重置 session 变量，回到 S0
- 用户输入含安全关键词 → 安全层拦截（PRD §4.4），不进入字段抽取

## 7. 法规依据

### 7.1 消毒产品分类（剂型枚举来源）

依据 **GB 38598-2020《消毒产品标签说明书通用要求》** §3 术语和定义：

| 大类 | 子类 |
|------|------|
| 消毒剂 | — |
| 消毒器械 | — |
| 指示物 | 生物指示物、化学指示物、灭菌物品包装物 |
| 卫生用品 | 抗菌制剂、抑菌制剂、隐形眼镜护理用品、**湿巾**、**卫生湿巾**、其他卫生用品 |

### 7.2 剂型枚举

依据 **2006 年《消毒产品标签说明书管理规范》** §[剂型、型号]：

> "消毒剂、抗（抑）菌剂的剂型如：'液体'、'片剂'、'粉剂'等等；禁止标注栓剂、皂剂。"

结合 GB 38598-2020 中卫生用品子类，本引擎 `dosage_form` 完整枚举如下：

| 剂型 | 法规来源 |
|------|---------|
| 液体 | 2006 规范 §[剂型、型号] |
| 片剂 | 2006 规范 §[剂型、型号]、GB 38598 §4.1(d) |
| 粉剂 | 2006 规范 §[剂型、型号] |
| 凝胶 | 行业通用，常见于抗菌/抑菌制剂 |
| 喷雾 | GB 38598 附录 A.1.4.1 示例（"口腔抑菌喷剂"） |
| 湿巾 | GB 38598 §3.10-3.11，卫生用品子类 |
| 其他 | 兜底（不匹配以上任一种时标记） |

**禁止标注的剂型**（2006 规范）：栓剂、皂剂。引擎收到此二类时标记为非法值，追问纠正。
