## 交付前检查清单

在把代码发给客户之前，确认以下事项：

- [ ] `.env` 中的敏感信息已清除（`ADMIN_KEY` 改成占位符，`DEEPSEEK_API_KEY` 用自己的）
- [ ] `SMTP_USER` 和 `SMTP_PASS` 已清空（让客户填自己的）
- [ ] `JWT_SECRET` 改为随机字符串提示（`change-me-in-production` 不安全）
- [ ] 运行 `python3 server/test_server.py`，确认 20/20 PASS
- [ ] `requirements.txt` 存在且内容完整
- [ ] `DEPLOY.md` 存在
- [ ] `run_prod.sh` 存在且可执行（`chmod +x`）

1. **这个系统需要什么环境？**

   - 一个 QQ 邮箱（发验证码用）

2. **部署要多久？**
   - 有技术人员的品牌方：30 分钟内
   - 没有技术人员的品牌方：建议我方协助部署（可收费）

3. **运行成本？**
   - 服务器：¥68/月（阿里云轻量）
   - DeepSeek API：按量计费，每次预审约 ¥0.01-0.05
   - QQ 邮箱 SMTP：免费
   - 合计每月 ¥100 以内

4. **怎么更新？**
   - 发新版代码 → 覆盖 `server/` 文件夹 → 重启服务即可

## 哪些地方客户最容易踩坑

| 坑 | 症状 | 一句话解法 |
|----|------|-----------|
| QQ 邮箱填了登录密码 | 验证码发不出去 | 必须用授权码，不是 QQ 密码 |
| 在 server/ 目录下启动 | ModuleNotFoundError | 回到项目根目录再启动 |
| 防火墙没开端口 | 外网访问不了 | 阿里云安全组放行 8000 端口 |
| 没装 Tesseract | OCR 不识别文字 | `apt install tesseract-ocr` |
| 多人共享 IP | 配额很快就用完 | Admin 面板重置，或各用各的网络 |

## 客户问"这跟别的合规工具有什么区别"

核心卖点（三选一，看客户在意什么）：

1. **省时间：** 不用人工翻法规原文，上传标签 30 秒出结果
2. **避坑：** 成分禁用/限用、医疗宣称拦截——这些是备案被拒最常见的原因
3. **可溯源：** 每个判定都有法规依据，不是黑箱 AI 猜的

